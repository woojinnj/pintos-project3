# Project 2: User Programs

## 구현

- 명령행을 공백으로 분리하고 사용자 스택에 문자열, `argv`, NULL 종료자와 가상 반환 주소를 구성한다. `rdi`는 `argc`, `rsi`는 사용자 공간의 `argv`를 가리킨다.
- `halt`, `exit`, `fork`, `exec`, `wait`, `create`, `remove`, `open`, `filesize`, `read`, `write`, `seek`, `tell`, `close`, 추가 기능 `dup2`를 처리한다.
- 사용자 버퍼의 전체 페이지 범위, 사용자 접근 권한, 읽기 목적지의 쓰기 권한을 확인한다. 문자열도 페이지마다 검사한다. 잘못된 접근 및 사용자 예외는 `exit(-1)`로 종료한다.
- `fork`는 사용자 레지스터, 주소 공간과 페이지 쓰기 권한, 파일 위치 및 실행 파일의 쓰기 금지를 복제한다. 부모는 자원 복제가 끝날 때까지 대기한다.
- 자식 종료 기록은 부모와 자식이 참조를 하나씩 소유한다. `wait`는 직접 생성한 자식에 한 번만 가능하며, 부모가 먼저 종료해도 자식은 자원을 정리하고 종료할 수 있다.
- 파일 시스템 연산은 공용 잠금으로 보호한다. `exec`는 열린 디스크립터를 유지하고 주소 공간과 실행 파일을 교체한다. 종료 메시지는 기존 프로세스 이름을 사용한다.
- `dup2`로 복제한 디스크립터는 파일 위치와 수명을 공유한다. `fork`는 부모와 독립적인 파일 객체를 만들면서 자식 내 별칭 관계를 유지한다.

## 한도

명령행 복사본은 NULL을 포함해 4 KiB 이내여야 한다. 문자열과 인자 포인터, 정렬 및 가상 반환 주소가 모두 4 KiB 사용자 스택에 들어가야 한다. 초과하면 프로세스가 안전하게 종료한다.

디스크립터 표는 프로세스마다 별도 페이지에 저장하며 번호 범위는 0–511이다. 초기 0과 1은 표준 입력과 출력이고, `open`은 2부터 빈 번호를 배정한다.

## 빌드 및 검증

저장소 루트에서 실행한다.

```bash
source pintos/activate
make -C pintos/userprog -j4
make -C pintos/userprog/build check -j4
make -C pintos/userprog/build grade
```

기존 userprog, 기본 파일 시스템, 메모리 부족 및 스레드 테스트에 `dup2` 2개와 추가 회귀 테스트 3개를 포함한다.

회귀 테스트는 많은 인자 및 스택 한도, 읽기 전용 메모리와 잘못된 버퍼 범위, 0바이트 I/O, 표현 불가능한 파일 크기, 고아 프로세스 및 중복/손자 `wait`를 검증한다.

`dup2`를 포함한 메모리 부족 경로를 검사하려면 사용자 프로그램을 다시 빌드해야 한다. Make는 컴파일 옵션 변경만으로 기존 객체를 다시 만들지 않으므로 먼저 정리한다.

```bash
make -C pintos/userprog clean
make -C pintos/userprog -j4 TDEFINE=-DEXTRA2
make -C pintos/userprog/build check -j4 TDEFINE=-DEXTRA2
```

## 검증 결과

- 전체 테스트 100개 통과: userprog 63개, 기본 파일 시스템 13개, 메모리 부족 1개, 스레드 18개, `dup2` 2개, 추가 회귀 3개.
- `EXTRA2`로 별도 빌드한 `multi-oom`의 10회 반복도 통과.
- 저장소 채점 기준: 기본 100.0%, `dup2` 추가 항목 포함 120.0%.
